# InterviewMate Linux 侧交接报告

> 产出：Windows 侧（InterviewMate-win），2026-11-28。交接对象：Ubuntu 侧维护者。
> 目的：两侧功能点与操作习惯保持一致。本文档列出 Windows 侧当前的**全部功能点与行为约定**，供 Linux 侧逐项排查核对；并标明哪些是新增功能、Linux 侧应该做成什么样子（只定义行为规格，不约束实现方式——用什么函数、什么库由 Linux 侧自选）。
> 背景约束：项目为两侧共用同一套 Python 代码（`app/audio`、`app/core`、`app/llm`、`app/runtime`、`app/vision` 等为跨平台共享层），平台相关层各自实现。Windows 侧仓库为 `D:\InterviewMate-win`（内部标识仍是 interviewmate）。

## 一、两侧一致的键位表（Linux 侧逐项排查）

| 键 | 普通模式 | 项目模式 |
|---|---|---|
| **F7** | 截图提交 | 截图提交 |
| **F8** | **按住**说话，松开自动提交 | **按住**＝开启截取窗口，松开＝窗口内面试官语句标记为问题并自动提交回答 |
| **F9** | 进入项目模式 | 退出项目模式（对话日志保留） |
| **F10** | 重新分析当前题目 | 查看/切回上下文视图（对话日志全文） |
| **F11** | — | 重开一轮（上下文清空，日志文件保留） |
| 界面内按键 | 输入框提交、F3 检索来源、Q 退出等不变 | 双路临时文字 `[我]` / `[面试官]` 常显 |

注：F8/F9 等热键为全局热键（Windows 用 AutoHotkey v2 实现），**失焦也生效**；全局热键接管后，应用界面短路自己的同名绑定，避免双触发。Linux 侧需找到全局热键等价机制（如桌面环境级快捷键），并同样做到「接管后界面短路」。

## 二、两侧一致的行为约定（Linux 侧逐项排查）

1. **触发类请求秒回**：所有「触发一个动作」的热键请求（语音开始/停止、截图、项目模式切换）都是先回执、动作后台执行——按键永远立即返回，绝不因为模型加载、生成慢而阻塞按键。Linux 侧排查自己的热键→动作链路是否有同步等待动作完成的写法（曾有「按一下卡半秒到一秒」的问题，根因就是同步等待）。
2. **录音中截图＝合并提交**：语音录音中按 F7 截图不单独提交，等录音结束后「语音转写文字 + 截图」合成一条请求发给模型；语音没识别出内容时截图单独提交。
3. **语音出字实时性**：流式 ASR 聚合阈值 200ms（原 600ms 导致出字延迟约 0.5 秒）。Linux 侧排查自己的聚合/分块参数是否有同样的「攒批等待」。
4. **识别纠错**：原约定「不做修正流程、对话日志存原版转写」已废止；现行方案为提交/落库前用 SenseVoiceSmall 重识别 + 拼音级热词纠正（行为规格见第六节）。发给回答模型的指令仍保留「问题来自语音转写可能不精准，先理解意思再以精准表述回答」；除该重识别外不新增修正用的额外模型调用。
5. **纯本地语音**：ASR 只用本地模型，不调用云语音服务（决策理由：主机走手机热点，网络质量波动大，云识别会断流）。
6. **角色污染**：只做人工控制（按键截取窗口），不做说话人分离、不做回声对冲。
7. **文档与代码同步**：Windows 侧已完成一轮 30 项文档-代码差异修复。Linux 侧排查自己的设计文档是否还写着旧行为（重点：热键语义、协议动作清单、模型目录、ASR 设备默认值）。

## 三、Windows 侧新增功能（Linux 侧应实现的行为规格）

### 1. 按住说话（push-to-talk）
- 普通模式：按住 F8 = 开始采集，松开 = 停止并自动把最终转写提交为问题。
- 替代了旧的「按一下开始/再按一下停止」切换语义；旧的切换动作仅作为兼容保留，界面内不再绑定。

### 2. 题目三分类 + 项目清单
- 给题型分类器注入一份**极简项目清单**文件（Windows 侧为 `config/projects.md`：每项目 4 行——名称 / 一句话定位 / 技术栈 / 核心技术主题，内容用名词短语，不用问句）。这份文件是给模型看的判断依据，不是项目总结文档。
- 分类器在原有题型（coding/normal，用于界面路由）之外，新增输出 `project_scope` 三类：
  - `simple`/`none`：纯简答题 → **不检索**；
  - `mixed`：简答题带项目（如「解释一下TCP，并说明你项目里怎么做的」）→ **检索**，输出「主体答基础，末尾一小段结合项目」；
  - `full`：项目题 → **检索**，项目视角为主。
- 保留两个兜底：检索总开关、强制项目模式（恒检索）。分类错类的代价是多等一次检索超时，不会崩。

### 3. 项目模式（本次最大新增）
- **进入/退出**：F9 切换。进入后两个 ASR 流同时工作，实现角色分工：**麦克风一路是考生（`[我]`），系统回环一路是面试官（`[面试官]`）**。线上面试时面试官声音走扬声器，系统回环天然能采到。
- **两个独立流式识别实例**：流式模型有内部状态，两路音频绝不能混喂同一实例；任何一路故障不影响另一路。
- **按句落库**：识别按句切分（句末标点/长度/时长阈值），逐句写入对话日志。
- **对话日志持久化**：目录 `logs/dialogues/`，每次会话一个 Markdown 文件，行格式 `HH:MM:SS [角色] 句子`；问题句加 `**[问题]**` 记号；退出/重开时文件保留，用于复盘。
- **F8 截取窗口**：按下＝开始记录窗口，松开＝把窗口内的**面试官**语句标记为问题并自动提交回答。用途：面试官会说很多非问题的铺垫，由考生按键决定「哪一段算问题」。
- **请求拼装结构**（发给回答模型的消息顺序，与缓存有关）：
  `[系统提示] → [对话日志按时间追加] → [本轮面试官问题] → [本轮检索内容]`
  外加两句指令：「检索出来的内容不一定对问题有用，请围绕问题回答」「面试官的问题来自语音转写可能不精准，先理解意思再以精准表述回答」。
  **要点：对话日志按时间顺序只追加、开头永不重排**——这样大模型服务的前缀缓存能命中（命中部分计费大幅降低）。检索内容放在问题之后，检索结果变化不破坏缓存。回答模型**不注入项目清单**（清单只给分类器）。
- **上下文管理**：F10 查看当前对话日志全文（界面临时切换视图）；F11 重开一轮（上下文清空、日志文件封存保留）。
- **界面**：状态栏显示模式（普通/项目）与会话 ID；双路临时转写按角色分行显示；快捷键提示栏随模式切换。

### 4. ASR 自检工具（命令行）
- **回放基线**：`asr-replay <wav>`——把一段已知音频直接喂给识别引擎，输出「整段重识别 + 热词纠正后文本」（ SenseVoiceSmall 链路，见第六节）。用于区分「识别不准」是模型问题还是音频链路问题（同一段音频回放结果稳定而麦克风差 → 问题在采集链路）。
- **测试音频**：Windows 侧仓库 `tests/assets/asr-test-question.wav`（16k/16bit/单声道，文案「解释一下什么是快速排序」，由 `scripts/windows/make-test-audio.cmd` 离线合成）。**直接拷贝到 Linux 侧仓库同路径使用**（wav 跨平台，无需重合成）。Windows 侧基线识别为「解释一下什么是快速排序」，逐字正确；Linux 侧 `asr-replay` 应得到相同文本，偏差大先查引擎加载与音频解析，再查模型。
- 注意：测试文案不要用字母缩写拼读（如 GDS）——TTS 按字母拼读后流式模型会识别成别的字母串（实测 GDS → ds），属模型对拼读的已知表现，会污染基线判读。
- **长对话基线音频**：`tests/assets/asr-dialogue-http2.wav` + 参考文本 `tests/assets/asr-dialogue-http2-ref.txt`（16k/16bit/单声道，约 145.7 秒，523 字不含标点，单人叙述——本机 SAPI 唯一中文声音为 Microsoft Huihui Desktop，无第二中文声音故不做双角色对话）。主题为 HTTP/2 特点讲解（多路复用、二进制分帧、HPACK 头部压缩、服务器推送、TCP 队头阻塞、与 HTTP/1.1 对比）；ref 逐句一行、与音频合成粒度一一对应（句间 300ms 静音，边界按合成顺序即行序推算），首行注释为说明，可整段回放亦可分句对照。
- **Windows 侧长对话基线结果**（FunASREngine，cuda，流式链路对照基线）：整段回放 CER 0.1472（47 错 / 523 字），分句回放 CER 0.1300。错点两类：英文缩写拼读——HTTP2/HTTP1.1/HTTP3 被 TTS 逐字母念出且数字念成汉字，模型吞字母（HTTP2 → ttp二/p二、HTTP1.1 → tp一点一、HPACK → sex、QUIC → k、TCP/UDP → cp/p）；中文同音字——帧→针、流→留、队头→对头、根除→根储。判读基线时按上述已知模式剔除后再比差异。**wav 与 ref.txt 直接拷贝到 Linux 侧仓库同路径即可复现同一基线**（音频资产跨平台，无需重合成）。现行 `asr-replay` 输出为 SenseVoiceSmall 整段重识别 + 热词纠正后文本，CER 指标见第五节结果表。
- **回环自检**：`loopback-test`——播放合成音频 → 从系统回环采集 → 识别 → 输出电平/文本/结论。链路通 = 录到声音（峰值非零）且识别非空。
- **测试音频合成**：离线合成一段固定文案的 16k wav（Windows 用系统自带 TTS）。
- Linux 侧等价物：回环采集用 PulseAudio/PipeWire 的 monitor 源实现 `loopback-test`；`asr-replay` 与合成脚本跨平台可直接共用。

### 5. 协议扩展
- 热键动作新增三个：`project-mode-toggle`（触发类，后台执行）、`context-view-toggle`（快操作，同步）、`context-clear`（快操作，同步）。协议动作总数从五个扩到十个；触发类动作的响应统一为「已受理」回执。

## 四、LLM 命名中性化重构（已完成，Linux 侧需同步）

- **目的**：LLM 接入层去除特定服务商命名耦合，统一为 OpenAI 兼容协议抽象；换服务商只改 `.env`，代码不动。
- **env 映射**（旧名废止）：

| 旧 | 新 |
|---|---|
| `DEEPSEEK_API_KEY` | `MODEL_API_KEY` |
| `DEEPSEEK_BASE_URL` | `MODEL_BASE_URL` |
| `DEEPSEEK_MODEL` | `MODEL_NAME` |

- **配置段映射**：`deepseek:` → `model:`（段内 `model:` 子键 → `name:`）；`providers.llm` 取值 `deepseek` → `openai`（OpenAI 兼容协议，可接 DeepSeek/GLM 等）。
- **符号改名**：客户端 `OpenAICompatClient`（`app/llm/openai_compat_client.py`）；分类器 `OpenAICompatQuestionClassifier`；异常 `ModelStreamError` / `ModelTimeoutError` / `ModelAuthError`；错误码 `E_MODEL_AUTH` / `E_MODEL_TIMEOUT` / `E_MODEL_STREAM`；UI 状态键 `MODEL`（`MODEL_VALUES`、`model_state`）；`RETIRED_MODEL_NAMES`。
- **验证**：全量 pytest 1632 passed；docs/ 全部同步。
- **Linux 侧影响**：Ubuntu 侧同名代码/文档/env 按上表逐一同步。换服务商只改 `.env` 三个值，示例（GLM）：`MODEL_BASE_URL=https://open.bigmodel.cn/api/paas/v4`、`MODEL_NAME=glm-…`、`MODEL_API_KEY=<服务商Key>`。
- **带图链路**：截图带图提交依赖 `GET {base_url}/models` 探测 `input_modalities`（`app/llm/openai_compat_client.py`）；智谱端点兼容性待实机验证。
- **生效条件**：主进程重启后才生效。

## 五、ASR 五模型对比实验与方案定案（已完成）

- **动机**：流式 paraformer-zh-streaming 同音字错误（帧→针、流→留、队→对、根储→根除等）；CTC 解码无语言上下文重打分，流式链路无法根治。
- **实验矩阵**：5 模型 × 无热词/热词两组；测试集 `tests/assets/asr-dialogue-http2.wav`（145.7s）；统一热词表 10 词。
- **结果**（整段 CER / 纯汉字 CER）：

| 模型 | 无热词 | 热词后 | 备注 |
|---|---|---|---|
| paraformer-zh-streaming（流式基线） | 0.1472（参照） | — | 现网链路 |
| paraformer-zh-large | 0.2487 / 0.0737 | 0.2383 / 0.0599（热词后处理） | 最弱：幻觉词、HPACK→flag |
| seaco-paraformer | 0.2278 / 0.0714 | 0.2209 / 0.0530（原生热词） | 中文热词有效（分针→分帧、对头→队头）；英文热词无效；无标点无 ITN |
| SenseVoiceSmall | 0.0713 / 0.0230 | 0.0557 / **0.0023**（拼音级热词后处理） | 推理最快 0.9s；唯一正确输出 HTTP2；后处理零误伤，9 处替换全对 |

（第 5 个模型 FireRedASR-LLM-S 因显存不可行排除，见「硬件约束备忘」。）

- **定案**：SenseVoiceSmall 离线整段重识别 + 拼音级热词后处理。
- **拼音滑窗匹配**：pypinyin 拼音序列编辑距离；2 字词仅同音替换；3 字以上允许编辑距离 1；保护区＝拼音且文字都相同的片段。
- **决策**：不上云 ASR（全部本地）；热词表由用户自行维护（`config/hotwords.txt`，每行一词，`#` 注释）。
- **硬件约束备忘**：FireRedASR-LLM-S（8.3B，约 16GB 显存）在 RTX 4060 Laptop 8GB 上不可行，已验证排除。实验用模型已删除；`models/` 仅保留 paraformer-zh-streaming、fsmn-vad、SenseVoiceSmall（897M）三个目录。
- **依赖**：pypinyin、jiwer 已装入 `.venv`。

## 六、ASR 方案实施行为规格（Linux 侧同步实现以此为准）

- **普通模式**：按住 F8 说话期间流式 partial 预览保留；松开提交前用 SenseVoiceSmall 对整段录音音频重识别 + 热词纠正，提交文本为重识别结果。
- **项目模式**：双流（麦克风＝考生、回环＝面试官）按句 flush 时，每句先重识别 + 热词纠正再落库对话日志。
- **SenseVoice 参数**：`use_itn=True`；rich text 标签（`<|zh|>` 等）清理后使用；device 优先 cuda、失败回退 CPU；模型加载失败降级用流式文本（仅 warning，不阻断）。
- **热词后处理**：模型无关通用模块，可单独复用；热词表不存在/为空时跳过纠正。
- **兼容性**：对话日志行格式不变；`asr-replay` 基线输出变为「重识别 + 纠正后文本」（`asr-test-question.wav` 基线句应逐字正确）。

## 七、Windows 侧已修复的问题（Linux 侧对照排查，很可能同样存在）

1. **ASR 模型加载失败（`model '...' is not registered`）**：两个根因——模型目录没有显式指向仓库内 `models/`（回落到了别处）；把本地目录名当成了模型注册名传给加载器（正确做法：本地目录名与模型注册名做双向映射，配置里两种写法都接受）。Linux 侧排查自己的模型路径配置与加载参数。
2. **热键卡顿**：按键动作同步等待整个回答生成完成，导致按键阻塞、失败提示连环弹。已改为先回执后台执行 + 失败提示去重（同一原因只提示一次，成功后清零）。
3. **截图提交阻塞**：界面提示写入无超时（界面忙时截图被无限拖住，已限时 1 秒）；带图提交同步等整条生成结束（已改为提交后后台生成）。
4. **提示词模板化**：内容层的硬性规定（层数/条数/字数/子点格式）全部删除，改为少量目标导向建议；保留输出协议。Linux 侧核对提示词是否同样残留硬数字。
5. **聚合延迟**：识别聚合阈值 600ms→200ms，出字延迟从约 0.5 秒降到 0.1 秒内。
6. **文档-代码脱节**：30 项差异（热键语义、协议清单、模型目录、设备默认值等）。Linux 侧同样要过一遍。
7. 环境类（Windows 专属，供参考）：AutoHotkey 脚本缺 UTF-8 BOM 导致中文注释破坏语法；Ollama systemd 服务指向残缺副本导致嵌入接口 500（已切到完整版路径）。

## 八、平台差异说明（Windows 实现不要求照搬，Linux 找等价物）

| 能力 | Windows 实现 | Linux 侧等价物（自行选型） |
|---|---|---|
| 全局热键 | AutoHotkey v2 常驻脚本（按下/松开事件、失败提示去重），由 `interviewmate.cmd start` 自动拉起，重复 start 靠 `#SingleInstance Force` 替换旧实例实现热键脚本重载 | 桌面环境级全局快捷键或同类工具，需支持按下与松开两种事件 |
| 系统声音采集（面试官一路） | WASAPI loopback（用户级安装的驱动差异可能导致个别输出端点录不到声，支持环境变量指定端点） | PulseAudio/PipeWire monitor 源 |
| 截图 | mss（跨平台，无需改动） | 同左 |
| 服务栈一键启停 | `stack.cmd up/down`（WSL keepalive + Dify 容器 + Ollama） | 对应的 shell 脚本（systemd user service 或 compose 命令封装） |
| ASR/嵌入模型 | FunASR 流式（paraformer-zh-streaming + fsmn-vad）+ SenseVoiceSmall 整段重识别（本地，`models/` 仅三目录，见第五节）+ Ollama bge-m3（Dify 嵌入） | 相同，模型目录约定见第七节第 1 条 |

## 九、配置与环境要求（Linux 侧核对）

1. `config/projects.md`：按 Windows 侧模板填真实项目（分类器判断依据）。
