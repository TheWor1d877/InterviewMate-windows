# 代码问题模式

算法题走另一套生成模式：左侧是阶梯式解题思路，右侧上方是思路块、下方是完整 C++ 代码。仍然只有两栏。

依赖：《3-文本输入与流式回答》。

本文件描述 Linux 侧实现，Windows 侧的对应实现与差异见《9-平台差异与Windows适配》。

## 交付物

```text
app/
├── llm/
│   ├── prompt_coding.py        代码题的 Prompt 与提交格式识别
│   ├── prompt_manager.py       按题型选 Prompt
│   └── stream_parser.py        framework 事件按 mode 分流
├── output/
│   ├── event_models.py         代码题事件结构
│   ├── event_dispatcher.py     代码事件分发与兜底拆分
│   └── response_normalizer.py  纯代码块的兜底提取
└── ui/
    └── panels/
        ├── navigation_panel.py 左侧阶梯思路
        └── answer_panel.py     右侧代码面板
```

## 左侧解题思路

按题目动态生成 2 到 5 个步骤，标题由实际题目决定。

```text
1. 理解题意
      |
2. 暴力算法
      |
3. 优化思路
      |
4. 复杂度分析
```

动态规划题可能是另一种拆法：

```text
1. 状态定义
      |
2. 状态转移
      |
3. 初始化与边界
      |
4. 遍历顺序
      |
5. 复杂度分析
```

左侧只放解题步骤、思路提示和当前步骤状态。不出现完整代码，不变成大段算法教程。每步的提示是一句话，说清这一步用什么方法、为什么，能脱离代码单独读懂。

## 右侧完整代码

右侧上方先给一个思路块，列出每步标题与一句话思路，内容与左侧阶梯同源；下面放完整代码，默认 C++17。

- 语法高亮。
- 缩进正确。
- 支持流式追加。
- 生成完整可读的实现。
- 思路块只列步骤标题与一句话方法，不写大段解题长文，不在代码里夹带解释。
- 不混入长篇文字。
- 不加第三栏。
- 不加独立的验证视图。

代码与思路块都在滚动容器里，鼠标滚轮可以上下翻，当前题目固定在滚动区上方。

右栏切到代码形态后是锁定的。代码题模式下后来混进来的普通事件不把已经显示的代码藏掉：普通表达单元与兜底文本在代码形态下直接忽略，右栏保留已显示的思路块与代码。兜底事件在代码题模式下被拆成代码正文与说明文字两路，代码正文追加到右栏，说明文字进左侧提示。

## 流式事件

`framework` 事件按 `mode` 分流：`mode` 是 `coding` 时承载 `steps`，其余取值承载 `sections`。同一份协议里两种形态并存，解析器按 `mode` 决定读哪个字段。

代码题的事件：

```json
{"type": "framework", "mode": "coding", "steps": [{"id": "p1", "title": "理解题意", "hint": "明确状态和约束"}]}
```

```json
{"type": "code_delta", "text": "#include <bits/stdc++.h>\nusing namespace std;\n"}
```

```json
{"type": "code_complete", "language": "cpp", "standard": "cpp17", "submission_mode": "acm"}
```

渲染顺序：

```text
framework
    |
左侧先显示思路阶梯
    |
code_delta
    |
右侧持续追加代码
    |
code_complete
    |
完成
```

普通题的四种事件（`framework`、`item`、`section_done`、`done`）不受影响，仍然按《3-文本输入与流式回答》流式事件协议一节处理。

## 提交格式识别

| 平台类型 | 输出格式 |
|---|---|
| LeetCode | 类和函数签名，不带 main |
| 牛客核心代码模式 | 按题目给的接口输出 |
| ACM 模式 | 完整 main、输入处理和输出 |
| 题面什么都没给 | 完整 main、输入处理和输出，按 ACM 模式处理 |

用户可以在配置里指定默认模式：

```yaml
coding:
  language: cpp
  standard: cpp17
  submission_mode: auto
```

`submission_mode` 取 `auto`、`leetcode`、`nowcoder`、`acm`。`auto` 由题目内容推断。

识别依据，按顺序判：

1. 题面出现 `class Solution`，判为 LeetCode。
2. 题面有函数签名形态，并且有返回值类型说明，判为 LeetCode。
3. 题面有输入输出格式或样例，判为 ACM 模式。
4. 题面只有函数签名形态、没有输入输出说明，判为牛客核心代码模式。
5. 都没有，判为 ACM 模式，按完整 C++17 实现处理。

返回值类型说明只认明说类型的形式：「返回 int」「返回值为」「返回值类型」「returns int」。「返回最大子数组和」这种描述性的说法不算返回值类型说明。

## 接口不明确时的兜底

函数名、类名或接口签名识别不准时，代码生成不失败。

处理顺序：

1. 优先用题目明确给出的函数签名。
2. 题目没给接口，按平台惯用形式推断。
3. 判断不出来，给出合理的 C++17 完整实现。
4. 关键假设放在左侧的简短提示里。
5. 仍然给出最重要的算法思路。
6. 不反复追问函数名和参数名。

算法正确性比接口名称猜测更重要。接口名字不准时，算法逻辑、状态设计、边界条件和复杂度分析仍然要正确。

## 纯代码块兜底

模型有时不按事件协议输出，直接给一段带代码块的文本。解析器在这种输出里识别出代码块，把内容追加到右侧代码面板，事件协议失效时的通用兜底见《3-文本输入与流式回答》。

一个代码围栏块聚合成一个事件，不按行拆：围栏块连首尾两行围栏标记一起交出去。整理模块再把这一块拆成代码正文与说明文字两路，代码正文进右侧代码面板，围栏之外的说明文字进左侧提示。围栏没闭合时，流结束时把累积的内容当成一个未闭合的代码块冲刷出去。

代码块前后有说明文字时，说明文字进左侧提示，不进代码面板。

## 代码验证

第一版不执行生成的代码。

后面要加编译检查时，规则是：

- 在独立临时目录里编译。
- 调用 g++。这是 Linux 侧的编译器，Windows 侧用 `cl.exe` 或 MinGW-w64 的 `g++`，见《9-平台差异与Windows适配》。
- 设置超时和资源限制。
- 不在主程序权限下运行不可信代码。
- 没有真实测试用例时不声称通过样例。
- LeetCode 函数模式需要构造正确的测试用例执行器才能验证行为。

验证状态只显示在顶部或轻量状态行里，不增加第三个面板。

## 验收

- 算法题的左侧是 2 到 5 个阶梯步骤，标题与题目相关。
- 左侧不出现完整代码；右侧代码上方是思路块，按「序号. 标题：hint」列出每步，与左侧阶梯同源，代码块内部不含解释。
- 代码逐块流式追加，语法高亮生效，缩进正确。
- 题目给了 `class Solution` 签名时，输出沿用该签名且不带 main。
- 题目给了输入输出样例时，输出带 main 与输入处理。
- 题目没给任何接口时，仍能给出可读的 C++17 实现，假设写在左侧提示里。
- 题目是项目里的算法题时，检索到的项目上下文进入代码生成的请求。
- 模型直接输出代码块而不是事件时，代码仍然出现在右侧。
