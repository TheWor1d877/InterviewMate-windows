# 总纲

InterviewMate 是运行在 Windows Terminal 里的面试辅助程序。它采集面试官的语音、桌面截图和用户手动输入的题目，把三种输入交给同一个问题处理模块，由 DeepSeek 生成可以直接说出口的回答或 C++ 算法代码，结果在终端左右两栏流式显示。

项目知识相关的题目先经 Dify 检索，再由 DeepSeek 生成。

## 使用方式

程序启动后终端呈现四部分：顶部状态栏、中间左右两栏内容区、底部文字输入框、输入框下面的快捷键提示栏。右栏顶部显示当前问题，题目在下面是回答内容。

三种输入方式：

- 按一次 F8 开始采集语音，再按一次停止，识别结果自动提交。
- 按 F9 抓取屏幕截图，图片自动提交理解。
- 在底部输入框敲回车提交题目，Shift+回车换行。

Windows 下全局热键由 AutoHotkey v2 绑定 F8 与 F9，终端失焦也能用：F8 交给 `voice-toggle`（切换语义），F9 交给 `screenshot`。AutoHotkey 用 `.venv\Scripts\python.exe -m app.cli hotkey <动作>` 静默调用 CLI，由 CLI 经 IPC 通知主进程。应用内的 F8、F9 绑定只在终端有焦点时生效，F8 为按一下开始、再按一下停止的切换语义。外部脚本同样可用 `interviewmate.cmd hotkey voice-toggle` 与 `interviewmate.cmd hotkey screenshot` 触发。

## 边界

InterviewMate 只在用户主动触发时采集语音或截图，并在独立终端显示结果。

它不负责这些事：

- 把生成的代码粘贴到 LeetCode、牛客或其他面试编辑器。
- 自动操作面试平台、自动点击面试软件、自动提交代码。
- 持续录制或自动监视整个桌面。
- 绕过面试平台的权限、监控或安全措施。

界面可以紧凑、低干扰，但不实现隐藏 AI 使用或规避监控的功能。

## 设计原则

**低延迟优先。** 减少没有产出的模型调用和中间处理。题型判断用规则，不为每道题多跑一次分类模型。

**输入统一。** 语音、截图、文本进同一个问题处理模块，不维护三套回答逻辑。

**流式优先。** 模型开始生成就显示内容，不等完整回答返回。

**检索按需。** 普通知识题和算法题不查知识库，项目相关题才查。

**两栏固定。** 普通题和代码题都用左右两栏。代码题右侧上方是思路、下方是完整代码，不加第三栏，不加独立验证视图。

**回答精简。** 生成面试时能迅速读完并组织成口头表达的内容。普通题每层 2 到 4 个表达单元，整题关键点 5 到 8 个，第一个关键点先给结论。

**容错优先。** 题目不完整、函数签名不明确、识别有错时给出合理方案，不停在原地追问。

**模块解耦。** 换模型、换检索框架、换语音引擎时不需要重写整个程序。

## 组件与依赖方向

```text
                        InterviewMate
                               |
                    Input / Hotkey Layer
                               |
        +------------------+------------------+
        |                  |                  |
     F8 语音             F9 截图            文本输入
        |                  |                  |
   Audio Capture      Screenshot API       Text Input
        |                  |                  |
     FunASR          DeepSeek Vision        Text
        |                  |                  |
        +------------------+------------------+
                               |
                      QuestionManager
                               |
                 题目整理 / 信息合并 / 去重
                               |
                 Question Classification
                               |
                    RetrievalPolicy
                               |
       +-----------------+-----------------+
       |                                   |
  普通知识/算法题                      项目相关题
       |                                   |
  DeepSeek API                          Dify RAG
       |                                检索项目资料
       |                                   |
       +-----------------+-----------------+
                         |
                    DeepSeek API
                         |
                   Stream Parser
                         |
                  Event Dispatcher
                         |
                      Textual UI
                         |
                左右两栏实时展示结果
```

依赖方向是单向的：输入模块只投递事件，不生成回答。问题处理模块不认识截图后端，也不认识检索框架的具体实现。模型客户端不认识检索模块。界面不直接请求任何外部服务。

平台相关能力走 `app/platform/` 门面：截图后端、音频设备枚举、进程通信、进程存活探测与编译器。`get_platform()` 是唯一选择平台的地方，上层模块不判断 `sys.platform`。

## 最终技术决策

| 功能 | 决定 |
|---|---|
| 项目名称 | InterviewMate |
| 操作系统 | Windows 11 |
| 开发语言 | Python 3.11 以上 |
| 终端 UI | Textual 与 Rich |
| 终端 | Windows Terminal（PowerShell 或 cmd） |
| 异步调度 | asyncio |
| 语音输入 | FunASR 本地 ASR |
| 系统回环音频 | WASAPI loopback（`soundcard`） |
| 语音快捷键 | F8 切换采集，停止后自动提交 |
| 截图输入 | `mss` 抓屏（整屏、主屏或指定屏） |
| 截图快捷键 | F9 截图后立即提交 |
| 全局热键 | AutoHotkey v2 绑定 F8、F9，静默调用 CLI |
| 手动输入 | 终端底部输入框，回车提交 |
| 多模态理解 | DeepSeek Flash |
| 普通问题生成 | DeepSeek 直连 API |
| 算法题生成 | DeepSeek 直连 API |
| 项目知识检索 | Dify Retrieval API |
| 最终回答生成 | DeepSeek 直连 API |
| 检索调用范围 | 仅项目相关问题 |
| Embedding | 沿用现有部署 |
| 默认代码语言 | C++17 |
| 普通问题布局 | 左侧回答框架加右侧关键表达 |
| 代码题布局 | 左侧阶梯思路加右侧完整代码 |
| 输出协议 | JSONL 流式事件 |
| HTTP 客户端 | httpx.AsyncClient |
| 进程通信 | TCP loopback + 随机 token |
| 默认录音保存 | 关闭 |
| 默认截图保存 | 关闭 |
| 编译执行 | 默认关闭 |

## 目标机器

Windows 11，NVIDIA RTX 4060，显存 8 GB。

Embedding 模型已经在 Dify 里跑着，InterviewMate 不再部署第二份。DeepSeek 走云端 API。FunASR 在本地跑，可以选 GPU 或 CPU，显存不足时回退 CPU。ASR 模型初始化失败不能挡住程序启动。

Dify 与 ASR 同时占显存时会发生竞争，启动时按 ASR 优先加载。
