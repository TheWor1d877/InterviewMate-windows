# 接口契约

外部服务当前的调用形态集中在这里。核实日期是 2026-11-25，来源是各服务的官方文档。

外部接口变了只改这份文档，各阶段文档引用这里的事实。内部数据结构、配置键、错误码写在《2-骨架与配置》和用到它们的阶段文档里。


## DeepSeek 模型标识与基址

模型标识是 `deepseek-flash`，基址是 `https://api.deepseek.com`，两者都从配置读取。

`deepseek-v4-flash-vision-exp`、`deepseek-v4-flash`、`deepseek-chat`、`deepseek-reasoner` 是已退役的名字。配置校验时拒绝这些值。

`deepseek-flash` 当前对应 DeepSeek-V4.1-Flash-1017，上下文 1048576 token，最大输出 393216 token，输入模态是 `text` 与 `image`，输出模态是 `text`。

官方视觉指南的示例代码里还写着 `deepseek-v4-flash-vision-exp`，那是 2026-08-21 的旧快照。模型名以 `GET /models` 的返回为准。

来源：[模型列表](https://api-docs.deepseek.com/zh-cn/api/list-models.md)、[视觉指南](https://api-docs.deepseek.com/guides/vision)

## DeepSeek 思考模式与推理强度

请求体带 `thinking` 字段，取值 `{"type": "enabled"}` 或 `{"type": "disabled"}`，默认 `disabled`。

请求体带 `reasoning_effort`，取值 `low`、`high`、`max`，默认 `low`。`none` 用于关闭思考模式，不在 `supported_levels` 列表里。

思考模式默认开启，默认档位是 `high`。关闭思考模式的写法是 `{"type": "disabled"}`。

## DeepSeek 文本请求体

向 `{base_url}/chat/completions` 发 POST，请求体带 `model`、`messages`、`stream`。`messages` 数组里每条消息的 `content` 是字符串。

响应是 SSE，`data:` 行承载增量内容，结束标志是 `data: [DONE]`。

## DeepSeek 多模态请求体

`messages` 数组里用户消息的 `content` 是数组，元素是 `{"type": "text", "text": "..."}` 或 `{"type": "image_url", "image_url": {"url": "data:image/<格式>;base64,<编码>", "detail": "auto"}}`。文字块与图片块放在同一个数组里。

`detail` 的取值：

| 取值 | 行为 |
|---|---|
| `low` | 缩放到 512×512，折算 384 token |
| `high` | 保留原图，等同于 `original` |
| `original` | 保留原图 |
| `auto` | 自动选择，当前等同于 `original` |

图片有三种传法：base64 数据 URL 内联、http(s) 外链、Files API 的 `file_id`。本地图片用 base64 内联。

## DeepSeek 图片输入限制

| 项 | 上限 |
|---|---|
| 单张图片 base64 解码后 | 32 MiB |
| 整个请求体 | 48 MiB |
| 单次请求图片数量 | 600 |
| 单张图片边长 | 8192 像素 |
| 单次请求图片总体积 | 64 MiB，不带 `file_id` 时 |

base64 编码让体积增加约三分之一，判断体积时按编码后的字节数算。

支持 JPEG、PNG、GIF、WebP，格式按文件实际内容判断，不看扩展名也不看声明的 MIME 类型。本项目只用 PNG 与 WebP。

推理前每张图会被缩放一次。总像素量低于约 544×544 的图按原比例放大，更大的图按原比例缩小，缩到总像素量约等于 1300×1300 的量级，每张图最多折算 1024 个 token。2000×2000 的照片和 5000×5000 的扫描件计费一样，缩图对费用没有收益，只有带宽收益。

## DeepSeek 模型能力探测

向 `{base_url}/models` 发 GET，响应 `data` 数组每项含 `id`、`input_modalities`、`output_modalities`、`context_window`、`max_output_tokens`、`effort`。

`effort` 对象含 `supported_levels` 与 `default_level`。

客户端启动时读一次，确认当前模型的 `input_modalities` 含 `image`。探测结果只用于展示：客户端不因缺少 `image` 而拒绝截图，采集与提交照常走；探测失败同样只告警不退出。见《4-截图输入与多模态》模型视觉能力一节。

## Dify 检索端点与鉴权

向 `{DIFY_BASE_URL}/datasets/{DIFY_DATASET_ID}/retrieve` 发 POST。

请求头带 `Authorization: Bearer {DIFY_DATASET_API_KEY}` 与 `Content-Type: application/json`。`DIFY_BASE_URL` 含 `/v1` 前缀。

## Dify 检索请求体

请求体含 `query` 与 `retrieval_model`。

`query` 最长 250 字符，超长时客户端截断到 250。

`retrieval_model` 的字段：

| 字段 | 说明 | 取值 |
|---|---|---|
| `search_method` | 检索方式 | `semantic_search`、`full_text_search`、`hybrid_search`、`keyword_search` |
| `reranking_enable` | 是否启用重排 | 布尔 |
| `score_threshold_enabled` | 是否启用分数阈值 | 布尔 |
| `score_threshold` | 分数阈值 | 浮点 |
| `top_k` | 返回片段数量 | 整数 |

这五个字段每次都要带，缺一个 Dify 就以 HTTP 400 拒绝请求。Dify 1.20.0 的检索端点**不继承**知识库里配好的检索设置，请求体里的 `retrieval_model` 会被逐字段校验。

默认值：`search_method` 是 `hybrid_search`，`reranking_enable` 与 `score_threshold_enabled` 都是 `false`，`score_threshold` 是 `0.0`，`top_k` 取配置值。

被服务端拒绝时映射到 `E_DIFY_REQUEST`，响应结构不对映射到 `E_DIFY_RESPONSE`，两者不要混。

外部知识库把 `retrieval_model` 换成 `external_retrieval_model`，字段名相同。内部知识库只用 `retrieval_model`。

知识库索引方式是 economy 时始终按关键词检索，忽略 `retrieval_model.search_method`。

## Dify 检索响应体

响应含 `records` 数组，每项含 `segment` 与 `score`。

| 要取的字段 | 位置                              |
|------------|-----------------------------------|
| 正文       | `records[].segment.content`       |
| 文档名     | `records[].segment.document.name` |
| 分数       | `records[].score`                 |
| 片段位置   | `records[].segment.position`      |

文档名在 `segment.document` 这个对象里，不是 segment 的直接字段。Dify 1.20.0 实测结构：

```json
{
  "records": [
    {
      "segment": {
        "content": "截图目标配置说明 ...",
        "document": {"id": "8fabceba-...", "name": "接口契约.md"}
      },
      "score": 0.6625407
    }
  ]
}
```

取文档名时兼容三处：`segment.document.name`、`segment.document_name`、`record.document.name`。三处都取不到时文档名落空字符串，该片段仍然保留。

来源：[从知识库检索分段](https://docs.dify.ai/zh/api-reference/knowledge-bases/retrieve-chunks-from-a-knowledge-base-test-retrieval)

## 截图后端（mss）

Windows 侧截图固定用 `mss`：纯 Python，没有系统级依赖，不弹确认框，抓到的位图转成 PNG 字节后只在内存里。

调用形态：`capture(target, monitor)`，返回 `Screenshot(data=PNG 字节, width, height)`，与上层约定的图片字节、宽、高一致。

三种截图目标：

| 取值 | 抓什么 | mss 取法 |
|---|---|---|
| `screen` | 整屏，多显示器时按桌面布局拼成一张 | `monitors[0]`，虚拟桌面包围盒 |
| `primary` | 只抓主屏幕 | 按主屏宽高在显示器表里匹配 |
| `monitor` | 抓 `screenshot.monitor` 指定的那块屏，序号 0 起数 | `monitors[序号 + 1]` |

目标以外的取值在配置校验阶段被拒绝。显示器序号越界或为负、`mss` 不可导入或初始化失败、抓屏失败、位图编码失败，统一抛 `E_SCREENSHOT`，程序继续运行。截图不落盘，PNG 字节直接交给图片处理。

## 音频后端（WASAPI）

设备枚举：麦克风用 `sounddevice` 的输入设备，系统回环用 `soundcard` 的 `all_microphones(include_loopback=True)` 枚举扬声器端点的 WASAPI loopback。回环设备的编号从 10000 起，与 PortAudio 的麦克风编号分开。

音频来源 `audio.source` 的四个取值：

| 取值 | 含义 |
|---|---|
| `microphone` | 麦克风输入设备 |
| `system_monitor` | 默认扬声器的 WASAPI loopback |
| `mixed` | 麦克风与回环各采一路，带来源标签 |
| `auto` | 默认麦克风与默认回环都有时混成一路（来源标签 `mixed`），只有一路时用那一路，都不通时报 `E_AUDIO_DEVICE` |

采集流程：按设备原生采样率与原生声道数开流（声道数封顶 2，超过按 2 开流后下混），下混单声道，重采样到 16000 Hz，再按 9600 点拼成 600 毫秒一块送进模型，块长关系见「FunASR 音频块参数」。上层拿到的永远是 16000 Hz 单声道。

## 进程通信传输层（TCP loopback 加 token）

Windows 侧用 TCP loopback：监听 `127.0.0.1` 上的随机端口，端口号写进 `runtime/interviewmate.port`，随机 token 写进 `runtime/interviewmate.token`。

客户端读端口文件与 token，连上后先发一行 token，再发一行 JSON 请求，读一行 JSON 响应，断开。服务端先读一行比对 token，通过后才交给协议层；token 不匹配直接断开。协议层（`app/runtime/socket_protocol.py`）不感知 token，请求字段 `action`、`request_id` 与响应字段 `ok`、`error`、`payload` 都不变。

本机隔离由 token 承担：token 存在只有当前用户可读的位置，端口只监听回环地址。

## 进程存活探测（psutil）

进程存活探测用 `psutil.Process(pid).is_running()`，不再用进程信号探测存活——信号方式在 Windows 上可能把目标进程直接终止。

判定链：先探 IPC 通道，通道通说明主进程在；通道不通再读 PID 文件，PID 存活说明主进程活着但 IPC 坏了，按异常处理；PID 文件不存在或进程已死，判定主进程没在运行。

`start` 前回收残留实例：探到活进程先发 `stop` 等其退出；没退出的按 PID 文件做身份校验（`is_app_process`，防止 PID 被复用后误杀别的进程），通过后 `terminate()`，等若干秒仍在就 `kill()`。

## 全局热键（AutoHotkey v2）

Windows 没有系统级的命令绑定机制，全局热键由 AutoHotkey v2 绑定：F8 交给 `voice-toggle`，F9 交给 `screenshot`。

脚本用 `python.exe -m app.cli hotkey <动作>` 静默调用 CLI，启动时隐藏窗口，不闪黑框、不改变当前焦点。不要用 `pythonw.exe`：没有控制台时 stderr 是 `None`，日志写到 stderr 会出问题。CLI 经上面的进程通信传输层自动带 token，把事件送给主进程。

也可以直接执行 `interviewmate.cmd hotkey voice-toggle` 与 `interviewmate.cmd hotkey screenshot`，等价于 `python -m app.cli hotkey <动作>`。应用内不再注册全局热键，终端有焦点时 F8、F9 由应用内按键绑定直接处理。

## FunASR 流式推理调用

模型用 `AutoModel` 加载。ASR 与 VAD 用两个独立实例，本地模型目录用 `model_path` 传：

```python
from pathlib import Path

MODEL_DIR = Path.home() / "models"

asr_model = AutoModel(
    model="paraformer-zh-streaming",
    model_path=str(MODEL_DIR / "paraformer-zh-streaming"),
    device="cuda",
)

vad_model = AutoModel(
    model="fsmn-vad",
    model_path=str(MODEL_DIR / "fsmn-vad"),
    device="cuda",
)
```

`model_path` 不能写成 `model_dir`：funasr 只在 kwargs 里存在 `model_path` 时才跳过 hub 下载，`model_dir` 不参与该判断，权重会被重新拉进 modelscope 缓存。

推理调用 `asr_model.generate`：

```python
result = asr_model.generate(
    input=chunk,
    cache=cache,
    is_final=is_final,
    chunk_size=[0, 10, 5],
    encoder_chunk_look_back=4,
    decoder_chunk_look_back=1,
    batch_size=1,
    disable_pbar=True,
)
```

`input` 是一段 float32 单声道波形。`cache` 是字典，`is_final` 是布尔值。

几条约束：

- 每条语音流新建一个 `cache` 字典，同一条流的所有块传同一个字典。跨流共享会让上一条的状态串到下一条。
- `batch_size` 固定为 1，一次调用只传一段波形。
- `disable_pbar=True` 关掉 funasr 的进度条。
- Paraformer 流式在 finalize 之后会重置内部缓存，冲刷完要把字典丢掉。
- 返回的文本只覆盖当前调用解码的片段，不保证是完整句子。
- ASR 实例不能带 `vad_model`。带 `vad_model` 时 `generate` 走 `inference_with_vad`，把 `chunk_size` 原样透传给 VAD，而两种模型的 `chunk_size` 类型互斥：paraformer 流式取列表 `[0, 10, 5]`，fsmn-vad 取整数毫秒。列表透传给 VAD 会抛 `TypeError: unsupported operand type(s) for /: 'list' and 'int'`。
- VAD 单独调用 `vad_model.generate`，`chunk_size` 传整数毫秒，实测取 600。

这段调用方式只适用于本地 Paraformer 流式检查点。把离线模型套一个 `cache={}` 当成流式用，不走这个路径。

Windows 上装 `torch` 要指定 CUDA 索引源：`pip install torch --index-url https://download.pytorch.org/whl/cu124`，PyPI 默认 wheel 是 CPU 版。ASR 默认 `device: cpu`，把显存留给 Ollama 与 Dify 的嵌入模型；显存够时可切 CUDA。

## FunASR 音频块参数

采样率 16000 Hz，单声道，float32。

`chunk_size` 取 `[0, 10, 5]`，单位是 60 毫秒帧，中项乘 960 得到每块采样点数，即 9600 点、600 毫秒。首项是回看帧数，末项是前瞻帧数。

`is_final` 在最后一块置 true，其余为 false。最后一块用 `is_final` 为 true 的那次调用冲刷剩余缓存。

`encoder_chunk_look_back` 与 `decoder_chunk_look_back` 的源码默认值是 0，上面的 4 和 1 是官方示例里的显式取值。

来源：[FunASR](https://github.com/modelscope/FunASR)、[paraformer-zh-streaming](https://huggingface.co/funasr/paraformer-zh-streaming)
